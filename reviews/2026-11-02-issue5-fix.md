# Issue 5: verification report/input separation

Base: `e1c47935c51c41b1765418c1587551eb03103696`. Both public verification functions now reject report paths aliasing the input or same-stem `.kicad_pcb`, `.kicad_sch`, `.kicad_pro`, `.kicad_prl`, and `.kicad_dru` context before CLI discovery/execution. Both the supplied and resolved input stems are protected. Normalized names and symlinks are resolved; existing hard links are compared by device/inode identity. Reserved same-stem paths are rejected even when absent.

Coverage is intentionally same-stem context, not an inventory of arbitrary hierarchical sheets, libraries or other project dependencies. This preflight does not exclude concurrent filesystem changes after validation. Callers needing that guarantee must isolate their working files from concurrent writers.

Additional cases cover resolved-input context, absent reserved paths, permission failures, symlink loops, and legal reports.
- `python3 -m unittest discover -s scripts -p 'test_*.py'`: 519 tests in 18.218 seconds; 513 passed and 6 existing geometry dependency skips. No failures.
- Differential calibration: the new reserved-context-path regression fails against the original module, which proceeds into KiCad instead of raising `REPORT_INPUT_ALIAS`.
- Real KiCad 10.0.5, disposable copy of `scripts/fixtures/open-net.kicad_pcb`: the original implementation with `report=board`, `parity=False`, `refill=False` returned status 5 and overwrote the board with `** Drc report`. The fixed implementation refuses direct and hard-link output aliases and preserves bytes. Separate safe reports before and after refusals return status 5 with 2 DRC violations, 2 unconnected pads and 0 footprint errors; board bytes remain identical. ERC alias coverage is mocked preflight testing, not a real ERC run.
- Runtime: five repetitions of 1,000 safe preflights, existing report and all five context files, measured 298.57, 295.64, 345.58, 316.06 and 306.30 microseconds per call. No caching; this is added preflight cost, not CLI runtime.

## Guard checklist

1. **Unevaluable input:** resolution/stat errors raise `REPORT_PATH_UNVERIFIED`; only missing optional paths are allowed. Missing primary inputs still fail existing checks.
2. **Monotonicity:** direct, normalized, symlink and hard-link aliases all fail. Permission errors and cyclic symlinks also fail; they cannot degrade into acceptance.
3. **Preconditions:** both public entrypoints invoke the check before CLI discovery, parity export, refill or report writes; tests assert discovery was never called on alias refusal.
4. **Source of truth:** current filesystem resolution and device/inode identity are queried on each invocation. The function implementation and regression fixtures are committed together; no derived or cached evidence is trusted.
5. **Persistence:** no cache or persisted clean state is introduced. Failed probes raise before a report is written.
6. **Provenance:** stable failure IDs distinguish established aliasing from unverified path identity. Same-stem and concurrency limitations are explicit above.
7. **Known-bad calibration:** original real-CLI input destruction was reproduced; the patched destructive invocation refuses and preserves the file. A new regression also fails on the original source.
8. **Fix vs mute:** unsafe report paths no longer reach KiCad, preventing the destructive write; ordinary report counts and violation status remain unchanged in the real safe-output control.

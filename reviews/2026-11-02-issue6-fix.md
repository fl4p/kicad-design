# Issue 6: preserve concurrent edits during promotion

Base: `e1c47935c51c41b1765418c1587551eb03103696`. Scope: GitHub issue #6.

Promotion retains its whole-set preflight and now checks each destination's original identity after
copying and fsyncing its temporary replacement, immediately before replace. Rollback likewise
checks the identity it recognized before replacing/removing it. Unexpected files, missing originals,
nonregular objects and failed probes raise explicit conflict/recovery errors. Temporary copies are
removed on refusal. A failed apply no longer returns a report claiming promotion was committed.

This is optimistic conflict detection. No filesystem compare-and-swap excludes an uncooperative
writer during the final check/replace or check/unlink interval. External editors/generators must be
quiescent. On unknown bytes, recovery stops and retains the journal; earlier promotions can remain
applied and the returned/persisted report says `recovery_required`, promotion `incomplete`.

## Guard checklist

1. **Unevaluable input:** only `FileNotFoundError` establishes absence. Other probe failures become
   `ConcurrentChange` or `RecoveryRequired`; symlinks/directories and deleted originals fail.
2. **Monotonicity:** edits, deletion, nonregular replacement, and permission failure never become
   acceptance. The tests include missing/new files and broken symlinks as far-tail cases.
3. **Preconditions:** callbacks execute after copying/fsync and before replacement. Real file
   operations, injected at the copy boundary, exercise both promotion and rollback call paths.
4. **Source of truth:** comparison uses full original identity including SHA-256. Recovery binds its
   final check to the identity whose digest it recognized; source and regression hashes are above.
   Existing request provenance already fingerprints the transaction implementation.
5. **Persistence:** conflicts do not mark journals committed/rolled back; unknown bytes retain the
   journal. No verification cache was introduced.
6. **Provenance:** public failure reports mark promotion incomplete, and the retained journal records
   per-file progress. Successful staged reports remain committed. Atomic exclusion is not claimed.
7. **Known-bad calibration:** the base implementation fails the new inter-promotion and rollback
   overwrite/unlink fixtures; the fixed version passes them and the legal controls.
8. **Fix vs mute:** unknown destination bytes now survive instead of being replaced; tests inspect
   actual contents, journal state, exception class, and public report rather than warning text alone.
